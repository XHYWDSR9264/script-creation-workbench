# 短剧生产SOP V2.0（闭环测试版）

## 一、设计原则

1. **先锁范围，再生成**：总集数、本次提交区间、生产路线、开头模板与硬节点是项目级参数，不能由正文生成任务自行改写。
2. **方案、正文、审计、检测分层**：模型生成不等于校准通过，AI深审不等于人工终审，朱雀分数不等于内容质量。
3. **所有证据绑定版本**：正文每次保存生成不可覆盖的新版本与SHA-256；AI深审、人工评分、朱雀报告和批准记录都绑定具体版本。
4. **新正文使旧终审失效**：G3以后产生新正文，流程自动回到G4；旧报告保留为历史，但不能放行新版本。
5. **先修事实，再修表达**：先排查因果、人物所知、道具、权限、时间空间、专业常识，再处理对白、表演提示和活人感。

## 二、完整执行链

### G0 立项与参数

- 锁定生产路线：授权IP改编、深度二创、完全原创/市场参考、定制卡点扩写。
- 锁定地区、呈现形式、题材、总集数、本次提交区间、单集时长、开头模板、内容质量门槛和朱雀门槛。
- 系统拒绝正文范围超过项目总集数。

**放行条件**：关键参数非空且范围合法，由人工批准。

### G1 方案与卡点

- 剧情梗概：只写全剧主线，不混入“第11—20集”式分集规划。
- 人物小传：身份、性格、动机、弱点、关系与成长，不用动作清单代替人物介绍。
- 世界观：时代空间、行业/异常规则、现实程序、能力边界与代价。
- 卡点矩阵：按本次提交范围写每集任务、冲突升级、现实代价、关系变化和结尾钩子。

**放行条件**：四项资料齐全，边界无冲突，由人工批准。

### G2 第1—3集校准

- 第一集开篇立刻出现可视化冲突。
- 三集内交代主角目标、关键关系、主要阻力和追看问题。
- 结构审计检查：集号、场次、范围泄漏、乱码、重复、括号、禁用包装词。
- 人工校准检查：声口、信息密度、表演空间、冲突升级和场景可拍性。

**放行条件**：校准稿覆盖前三集，结构审计通过，人工确认后批准。

### G3 分批创作

- 每批原则上不超过10集；本次只生成已锁定的提交区间。
- 每集有独立任务、关系变化、现实成本和有效钩子，不使用同一种“发现证据—继续复核”循环。
- 每批结束更新连续性账本：人物、地点、时间、道具、权限/证照、伤病与资金状态。

**放行条件**：最新正文完整覆盖本次提交区间，且G2已通过。

### G4 内容终审

- 结构审计不是内容终审。
- AI内部深审执行八维评分与五张反查表，硬错误为0，核心维度过线。
- 编剧/编辑依据原文证据录入人工内容质量分，默认不低于90分；要求95分的项目按95执行。

**放行条件**：当前最新正文同时具备“AI内部深审通过”和“人工内容质量评分达标”，再由人工批准。

### G5 朱雀同版检测

- 只送检当前提交范围的纯正文。
- 保存真实人工特征、疑似AI、AI特征和报告截图；系统绑定当前正文SHA-256。
- 默认人工特征不低于85%。未取得真实结果时只能标记待检，不能估分或虚报。

**放行条件**：当前最新正文报告达标，再由人工批准。正文改动后自动失效并退回G4。

### G6 交付与归档

- 选择当前最新且覆盖提交范围的正文。
- 套用老王/大麦开头模板，模板只影响正文之前部分。
- 生成DOCX/PDF后执行：正文重提取逐行比对、首页报告绑定、文件名检查、全页渲染抽检。
- 阶段稿必须准确标注实际提交范围，不冒充全集完本。

**放行条件**：当前版本G4与适用的G5均通过，交付文件复检完成，由人工归档。

## 三、完整任务测试记录要求

收到测试任务后，必须留存以下证据：

1. 项目ID、参数快照和素材SHA-256。
2. G0—G6每一步开始时间、完成时间、阻塞原因和人工决定。
3. 第1—3集校准稿、累计提交稿及每个正文版本SHA-256。
4. 结构审计、AI内部深审、人工评分和朱雀报告的同版关系。
5. 连续性账本更新记录与最终交付文件复检结果。
6. 若某一步失败，记录最早的不确定点，修复后从该节点继续，不从头盲目重跑。

## 四、软件自动阻止的错误

- 未完成前序闸门便跳关。
- 对已通过闸门重复批准。
- 正文范围超过总集数。
- 用历史正文的AI深审、人工评分或朱雀报告批准当前正文。
- G4缺少人工内容质量分。
- G6缺少当前版本的内容终审或朱雀证据。

## 五、仍需人工负责的判断

- IP授权与改编边界是否合法、是否符合委托要求。
- 人物行为是否可信、情绪是否成立、专业细节是否足够真实。
- 朱雀截图与数字是否来自真实检测页面。
- DOCX/PDF视觉版式、首页报告位置和最终投稿文件是否正确。
